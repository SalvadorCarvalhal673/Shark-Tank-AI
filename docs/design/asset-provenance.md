# Asset licensing and provenance

Issue #13. Every production asset the app ships is recorded in `docs/design/asset-manifest.json` with:

- **Creator** — who made it.
- **Source** — where it came from.
- **Licence** — the licence it is used under.
- **Version** — the exact version recorded.
- **Modifications** — what was changed from the original, if anything.
- **Redistribution rights** — whether and how it may be passed on.
- **Notices** — the notice files that must travel with it.
- **Verification status** — whether the record has been checked, and how.

The manifest lives in `docs/design/`, not `public/studio/`. That keeps it out of the files the site serves, and keeps the existing rule that `public/studio/` contains only the cast file (`tests/studio-materials.test.ts`).

`tests/studio-provenance.test.ts` keeps the record honest:

- Every asset file in `public/` and `src/` (models, images, fonts, icons, audio, video) must be recorded.
- Each recorded file must match its recorded size and SHA-256. Changing the cast file without updating the manifest fails the test.
- Every record must fill every field, every notice and source file it names must exist, and verified records must say how they were verified.
- **Unverifiable 3D assets are rejected:** every record in the 3D workstream must be `verified`. A record outside the 3D workstream may be `unverified` only with an open finding.
- Runtime 3D libraries must match the installed version and declared licence.
- The cast file must be self-contained: no external buffers, no images, no required decoder extensions. The studio source must reference no remote URL.

## Open decisions for the group

**DECISION (open, for the group):** no public licence has been applied to the project's original work: the characters, room, code and presets. The manifest says so rather than inventing one. Until the group chooses a licence, the original assets may travel with the repository, but nobody outside the group has a granted licence to reuse them. Public deployment stays prohibited while SE-001 is open.

**Favicon (resolved, Issue #84).** The earlier icon had no recorded source, so it could not be verified. It was replaced by an original icon drawn in code (`scripts/create-favicon.mjs`, a fin above a wave in the app's colours).

## Adding an asset

1. Put the file under `public/` (or `src/app/fonts/` for fonts), with any licence notice next to it.
2. Add a record to `docs/design/asset-manifest.json` with every field, the file's size and SHA-256, and how you verified it.
3. Run `npm test`. The provenance test fails until the record matches the file.
4. Assets whose creator, source or licence cannot be verified must not be added to the 3D studio.
