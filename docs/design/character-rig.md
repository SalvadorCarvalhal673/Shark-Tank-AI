# Character rigging strategy

Issue #8. This document defines how every investor character is built, animated and instanced. Issues #5–#7 (production characters), #9 (posture and gestures) and #10 (reactions) build on it. The contract is code: `src/features/studio/rig.ts`, enforced by `tests/studio-rig.test.ts`.

## Decision

**One cast file, one shared skeleton, one shared clip set.** `public/studio/investor-v1.glb` holds:

| Part | Name in the file | Shared? |
| --- | --- | --- |
| Seated skeleton (15 bones) | `Pelvis`, `Chest`, `Head`, `Left/RightArm`, `Left/RightForearm`, `Left/RightThigh`, `Left/RightShin`, plus facial `Brows`, `Left/RightBrow`, `Jaw` (added in Issue #5) | Whole cast |
| Body mesh | `Cast_Body` | Whole cast: same proportions for every investor |
| Feature mesh per investor | `Cast_maya`, `Cast_adrian`, `Cast_sofia` | One investor each: hair, accessories, face details |
| Clips | `Listening`, `Offering`, `Withdrawal` | Whole cast |

All meshes are bound to the same bones. At runtime, `createInvestorInstance` (`avatar.ts`) clones the file with SkeletonUtils, removes the other investors' feature meshes, and gives the instance its own skeleton, mixer and materials.

**Alternatives considered:**

- *One file per investor.* Each file would repeat the skeleton, body and clips, about three times the download, and the clip sets could drift apart.
- *Three full rigs in one file.* glTF loaders rename duplicate bone names (`Head`, `Head_1`, …), which breaks shared clips.
- *Per-investor bodies.* This would break the existing guarantee that instances share body geometry in GPU memory, and the "consistent cast proportions" asked for in Issue #7.

## Rules

1. **Bones.** The names, hierarchy and rest offsets in `RIG_BONES` are the animation binding keys. Never rename a bone per character. A new bone must be added to the contract and to the generator together.
2. **Clips.** Each clip is authored once against `RIG_BONES` and plays on every investor. Clips may only rotate bones, never translate or scale them, so seated proportions and the chair fit (`tests/studio-room-fit.test.ts`) hold in every frame. New clip names (for example Issue #9's explanation gesture) are added to `RIG_CLIPS`.
3. **Features.** Hair, glasses, buns, jewellery and face details go in the investor's feature mesh, skinned to the bone they move with (usually `Head`). They then follow every clip automatically. Unskinned attachments added in React are not allowed. Adrian's glasses were moved from `scene.tsx` into his feature mesh for this reason.
4. **Materials.** Every primitive uses one of the `RIG_MATERIALS` slots (`Skin`, `Jacket`, `Trousers`, `Hair`, `Brass`, `Shirt`, `Eyes`). `avatar.ts` recolours the slots per investor, and each instance owns its material clones.
5. **Seated proportions.** The rig must stay inside the measured seated envelope (`SEATED_BODY` in `room/layout.ts`). The fit test measures it over every frame of every clip and fails if a new body or clip no longer fits the furniture.
6. **Ownership.** Each instance owns its skeleton, mixer and materials and disposes them; geometry is shared with the loader cache. Cameras, selection and animation completion never dispatch financial actions (`AGENTS.md`).

## Source

Everything is generated by `scripts/create-studio-avatar.mjs`, which imports the contract directly:

```
node scripts/create-studio-avatar.mjs
```

The file name stays `investor-v1.glb` so existing fault-injection tests and loader paths keep working.

## Enforcement

`tests/studio-rig.test.ts` checks:

- The skeleton, hierarchy and rest pose match `RIG_BONES`.
- The clip names match `RIG_CLIPS`, and every track only rotates a contract bone.
- There is one body and one feature mesh per investor, all bound to the same bones, using contract material slots.
- Each instance keeps the body and only its own features, sharing its own bones.
- Instances have independent skeletons and mixers but share body geometry.
- Adrian's glasses keep a constant offset from the head while the Withdrawal clip turns it.

## Measured impact

| Measure | Before | After |
| --- | --- | --- |
| Cast file | 175,708 bytes | 214,364 bytes (three feature meshes, glasses now skinned) |
| Panel view triangles / draw calls | 29,662 / 48 | 29,674 / 50 |
| Skeletons / mixers in the studio | 3 / 3 | 3 / 3 |

Each investor's features add one draw call per material they use. With 60 as the phone budget, Issues #5–#7 should keep each investor's features to two or three material slots, and Issue #12 can merge slots if needed.
