# Scripted continuation — #51
fallback.ts adapts existing required questions and opening/counter/outcome reason maps. It never invents a rejection/acceptance, recalculates terms, changes the journal, saves data or dispatches actions. A revised offer is not a completed deal. Financial values remain separate read-only context facts.

Reasons: missing credentials, timeout, refusal, network failure, invalid output, exhausted budget, no consent and cancellation. Provenance scripted, exact reason and limitations are explicit. Stale cancellation should normally be discarded by lifecycle rather than rendered. Existing founder drafts remain owned by gameplay; this adapter cannot mutate them.

No auto retry, repair loop or second provider. Mode changes preserve the same engine/controller. Existing application does not yet call this adapter; mock integration can use it without keys. Tests assert unchanged state/budget and exact committed withdrawal/acceptance explanations. SE-001 open; no public deployment.
