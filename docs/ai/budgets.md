# Token, cost and request controls — #54
BudgetController uses integer nanodollars/BigInt and reserves worst-case costs BEFORE work; immutable leases settle once. Defaults:8000input/2000output tokens per request (including billed reasoning),16attempts per episode including failures/retries,128requests per process,2global active requests/1per server-resolved principal,64principals,5USD process-wide cap,15s deadline. No automatic retries. Episodes include optional clarification allowance; base ten-call cost scenario is not the maximum.

Server/principal/global controls are independent of browser session identity. Principal must be derived by the future trusted server boundary, never accepted from BrowserRequest. Resetting a run cannot bypass global request/spend limits. Maps are bounded by global request/principal ceilings; no timed eviction that permits duplicate billing. Exhaustion -> honest scripted fallback. Global reservation makes concurrent check-and-reserve atomic within one synchronous JS process. Missing/invalid usage or failed/cancelled provider call charges full reserved cost; known safe actual usage can settle lower.

Input wire limit128KiB and response16KiB are contract bounds; provider input must separately satisfy token limits. Future adapter must use trusted token accounting including system/schema/history and hard output caps. Character counts are not tokens. The mock runner uses a deliberately conservative UTF8-byte upper bound plus schema overhead as a synthetic preflight budget, not a measured vendor tokenizer.

Limitations: memory ledger resets on process restart; no synchronization across serverless instances/workers, no durable global cap, no identity authentication or IP-proxy abuse protection. Provider abort may not stop billing/remote work; logical concurrency slots cannot guarantee cancellation of remote jobs. Public paid exposure needs separately approved durable limits/identity/exposure design, account spend caps and security sign-off. No Redis/auth/infrastructure added speculatively. No live endpoint.
