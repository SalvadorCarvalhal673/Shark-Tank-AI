# Request lifecycle — #50
RequestLifecycle owns only transient conversation requests/events, never game state. The caller synchronizes run/revision/investor/presentation-mode/recovery identity via setContext before begin and before accepting results. A context change aborts pending work and increments conversation epoch. Explicit cancellation and disposal invalidate even at unchanged financial revision. A new request supersedes the old request; exact IDs reject out-of-order results. consume applies once; presentationFinished also applies once. Dedup retains128 IDs per controller lifetime; exhaustion fails closed, no eviction that could replay old IDs.

Integrating gameplay must invoke setContext on restart, acceptance/closure or any engine action, investor switch, recovery and view-mode change; dispose on unmount. No current component is changed. A contract cannot observe external UI state automatically. Events request-started/dialogue-ready/presentation-finished/request-cancelled carry full bindings and only drive presentation. Offers/withdrawals come from engine events.

withDeadline composes AbortController and a rejecting race, cleans timers/listeners and handles providers that ignore cancellation. Absolute maximum15s; ordinary latency target2–4s. Cancellation does not guarantee a provider refunds tokens. Late success cannot be consumed. No retries or extra actions. SE-001 open; no deployment.
